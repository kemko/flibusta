# Индексация книг, поиск авторов, сборники FB2 и OIDC

## Overview

Добавить индексацию FB2/EPUB, сведения об иллюстрациях и переводчиках, поиск авторов по алиасам и опечаткам, корзину для создания сборника FB2, скачивание и отправку через SMTP. Закрыть веб-приложение через OIDC; для OPDS предоставить отдельные отзываемые ключи.

## Решение по сборке

Сохраняется явно заданный итоговый формат FB2. Выбирается непосредственная сборка FB2: исходные FB2 переносятся без промежуточной конвертации, EPUB преобразуются через Calibre с адаптером для сохранения оглавления и внутренних ссылок. Предложенный вариант fb2cng → EpubMerge изучен:

- fb2cng поддерживает FB2 → EPUB 2/3, включая оглавление и переводчиков. CLI: fbc convert --to epub2 --output-file result.epub source.fb2.
- EpubMerge имеет самостоятельный CLI с зависимостью six. Запуск через calibre-debug --run-plugin вызывает тот же код; устанавливать Calibre исключительно ради слияния EPUB необязательно.
- EpubMerge переносит ресурсы книг в отдельные каталоги и умеет вкладывать исходные оглавления под названия книг. Для сохранения оглавления из единственного пункта нужен --keep-single-tocs.
- Проверка самостоятельного ядра EpubMerge 3.3.0 на синтетических книгах подтвердила: два NCX сохраняют вложенные пункты; два EPUB с оглавлением только в nav.xhtml дают пустое оглавление; смешанный набор теряет пункт книги без NCX. Переводчики в метаданные результата не переносятся.
- Для требуемого FB2 эта цепочка дополнительно потребует EPUB → FB2. Все исходные FB2 пройдут двойную конвертацию, а исправления экспортера Calibre всё равно понадобятся.
- В FB2-экспортере Calibre обнаружены ограничения: внутренние ссылки пропускаются; обработка оглавления без фрагментных якорей не гарантирует сохранения вложенности. Обычного ebook-convert недостаточно для выполнения требований. Поэтому собственное объединение уже подготовленных FB2 здесь проще по составу зависимостей и уменьшает число преобразований. Собственный универсальный конвертер EPUB не создаётся: обработка XHTML остаётся в Calibre, приложение добавляет недостающую работу со структурой и ссылками. fb2cng и EpubMerge в рабочие образы не включаются. Если итоговый формат впоследствии изменится на EPUB, выбор следует пересмотреть.

## Context

- Проект использует PHP 8.1, PostgreSQL, nginx и Docker Compose. Автоматической тестовой инфраструктуры нет.
- application/tools/app_update_zip_list.php определяет диапазоны bookid по названиям архивов, содержимое книг не анализирует.
- Общие представления книг находятся в application/functions.php: book_info_pg, book_small_pg, opds_book.
- Веб-поиск и OPDS используют отдельные запросы. Поиск авторов проверяет фамилию, основной поиск книг — название.
- Алиасы представлены в libavtorname.masterid. Предыдущее исследование дампа установило связь автора 191202 «Френк Герберт» с 4717 «Фрэнк Херберт». Текущий поиск эту связь не учитывает.
- application/tools/cleanup_db.sql удаляет авторов без собственных книг, включая алиасы и переводчиков. Таблица libavtoraliase есть в схеме, но её дамп не предоставлен.
- Корзины, SMTP и OIDC нет. Существующий идентификатор книжной полки не является авторизацией.
- В LibFlib/lib.flib найдены FB2; EPUB и пограничные случаи нужно представить небольшими собственными тестовыми файлами.
- Новые зависимости: PHPUnit, Jumbojett OpenID Connect, PHPMailer; Calibre — только в обработчике преобразования. Для нечёткого поиска использовать pg_trgm.
- Основные точки интеграции: application/init.php, functions.php, public/*.php, modules/*, opds/*, tools/*, docker-compose.yml, phpdocker/*.

## Development Approach

- Testing approach: Regular — реализация, затем регрессионные тесты.
- Выполнять задачи последовательно. Каждая задача включает новые или обновлённые тесты; все накопленные тесты должны проходить перед следующей задачей.
- Единая команда проверки: tests/run.sh. Тестовые БД, OIDC и SMTP изолированы от рабочих сервисов.
- Полный дамп и предоставленные архивы не изменять. Стандартные тесты используют собственные небольшие fixtures.
- Дополнительные данные хранить отдельно от импортируемых таблиц; повторный импорт не должен удалять результаты сканирования, задания и ключи.
- Корзина принадлежит сессии. Профили пользователей не создавать. Для владения ключами хранить только непрозрачный HMAC от проверенных issuer и subject, без имени, email и исходного subject.
- Индексация и генерация работают через CLI, состояние — в PostgreSQL. Отдельный брокер сообщений не нужен.
- Иллюстрации: уникальные ресурсы JPEG/PNG/WebP за вычетом явно обозначенной обложки. Повторные ссылки не увеличивают число; разные ресурсы с одинаковыми байтами считаются отдельно. Не угадывать обложку по имени файла.
- Нулевое число иллюстраций, отсутствие результата и ошибка обработки различаются.
- До подключения зависимостей проверить лицензии, advisories, поддерживаемые версии, совместимость и транзитивный состав; версии закрепить. Внутренний API Calibre проверять регрессионными тестами при обновлении.
- Покрытие новой бизнес-логики PHP и адаптера Python — не менее 80%; сторонний код и несвязанный существующий код исключить.
